# Аналіз планів виконання запитів та індексування БД

## Огляд

Було проведено аналіз планів виконання запитів за допомогою команди `EXPLAIN` для полів, що використовуються при частому пошуку та фільтрації. За результатами аналізу всі необхідні індекси вже присутні в БД.

---

## Методологія

Для кожного поля що використовується в умовах `WHERE` виконувався запит:

```sql
EXPLAIN SELECT * FROM <таблиця> WHERE <поле> = <значення>;
```

Ключовий показник — колонка `key`:

- `key = назва_індексу` → індекс використовується ✅
- `key = NULL` → повне сканування таблиці, потрібен індекс ❌

### Таблиця `users`

**Запит 1 — пошук по email (використовується при логіні):**

```sql
EXPLAIN SELECT * FROM users WHERE email = 'admin@test.com';
```

| type  | possible_keys | key   | rows |
| ----- | ------------- | ----- | ---- |
| const | email         | email | 1    |

✅ Індекс `email` використовується. MySQL знаходить запис за 1 крок.

## Висновок

Всі необхідні індекси вже присутні в базі даних. Вони були створені автоматично MySQL у двох випадках:

**1. UNIQUE constraints** — для полів `email` та `username` в таблиці `users`, оголошених як `unique: true` в міграції Sequelize. MySQL автоматично створює індекс для кожного унікального поля.

**2. Foreign Keys (зовнішні ключі)** — для полів `user_id`, `country_id`, `team_id` тощо. MySQL автоматично індексує поля зовнішніх ключів для забезпечення швидкого пошуку при JOIN операціях.

Додаткового створення індексів вручну не потрібно — всі поля що використовуються при частому пошуку та фільтрації вже проіндексовані.
